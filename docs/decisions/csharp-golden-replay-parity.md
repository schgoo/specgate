# Native C# goldens and implementation-to-implementation replay checks

> **Status:** accepted
> **Owner:** SpecGate maintainers (human-ratified)
> **Date:** 2026-10-20
> **Issue:** [#47](https://github.com/schgoo/specgate/issues/47)

## Context

C# capture now runs ordinary tests against a woven build and publishes native
CTSC bundles. The golden matrix still checks only C# registries, leaving its
behavioral producer outside the generated trust anchor. Interim in-process
weaver and setup tests also duplicate the retained paired behavior corpus.

The issue originally requested strict comparison of independent Rust and C#
reference captures. CTSC Strict pairs scenarios by name, but native frameworks
name their tests differently. Matching or renaming independent scenarios would
introduce a second, unnecessary scenario-selection mechanism.

## Decision

### Ratified correction: one golden bundle for all languages

The maintainer's 2026-10-20 correction supersedes both the original issue's
dual artifacts, this ADR's earlier requirement to retain Rust behavioral goldens,
and the interim correction retaining implementation-specific registry snapshots.
There is **one** checked-in golden bundle per component/scenario set for **all**
implementations and languages, including its canonical registry.

The internal matrix is version `0.2.0`, with no compatibility reader. Captured
component rows declare `reference: { implementation, artifacts }`, selecting
exactly one successful discover-and-capture binding endpoint and exactly
`manifest.json`, `reference.otlp.json`, and `registry.ctsc.json`. A discovery-only
component selects one successful discovery endpoint with only
`registry.ctsc.json`, no behavioral files and no checks. Negative and replacement
rows have no reference or checks.

The maintainer additionally ratified flattening on 2026-10-20: the layout is
`component/<id>/{manifest.json,reference.otlp.json,registry.ctsc.json}`, without
the formerly organizational `reference` subdirectory. Reference selection and
the single-oracle semantics are unchanged; no matrix-version bump is needed.
Successful components have no implementation directories
or per-language artifacts. Negative error artifacts are unchanged.
The current fixture configuration selects C# for paired captured rows and Rust
for Rust-only captured rows. This is explicit fixture configuration, not a
harness language preference; language is an endpoint property, not its identity.

The selected native producer writes **directly** into the component directory,
so native encoding records its basename as `target.name` (for example,
`fixture.stateless_add`) and the actual producer's language. This truthful
provenance change is ignored by the existing comparison policy; no policy is changed.
Scenario names and recorded stimuli are untouched. No trace is copied,
translated, or relabelled; digests are generated by the existing capture path.

### Independent native producer validation

Generate C# registries, reference traces, and manifests from the existing
`SpecGate.CtscFixtures` assembly and its ordinary native tests. Never translate
Rust artifacts into C# artifacts. Preserve both producers' capture phases:
nonselected native captures go to invocation scratch under
`producer-captures/<row>/<implementation-directory>`, and are not byte-checked
as separate behavioral snapshots. Independently obtain each producer's full
native registry, including dependency closure and ordering, in scratch. Validate
each native bundle against its **own** registry, never a substituted canonical
registry. Only the selected native registry is published as the shared oracle.

Build the C# tests once per batch. Reflect over the woven assembly used by those
tests, retain all discovered component schemas, and validate every published
bundle as Trace Core, Linked, and bundle-conformant. The same rule applies to
Rust. A linkage failure is a product defect, not an exception declaration.

Every enumerated test must pass during golden capture. Every discovered
operation, including nested calls, must appear in a trace unless an exact
operation, stable code, and reason declare its capture limitation. Failed or
skipped tests do not contribute scenarios. A passing test may intentionally
observe a declared operation error or catch a target exception; those operation
outcomes remain in the recording.

### Replay checks identify implementation versions

Use a list of reference-to-candidate checks, not separate replay fields for
languages. Each endpoint names an implementation through the shared binding.
The implementation is a particular version of the code selected by that
binding; its language is a property, not the endpoint's identity. The fixture
versions in this slice are the versions in the current repository checkout.
No new version selector, checkout manager, or worktree mechanism is introduced.

Every captured row requires checks whose `reference` equals the selected
endpoint. Retain only the existing selected-endpoint-to-Rust checks, with their
existing modes, reasons, and exact unsupported categories. Nonselected producers
do not need separate replay checks. Every check resolves the shared reference
directory. Each verified check replays that bundle's
recorded top-level stimuli on the candidate and compares the resulting native
trace with the reference using `ctsc.strict/0.1.0`. Replay carries the reference
scenario names, so no independent test-name pairing is needed.

Support and limitations belong to each endpoint pair. Duplicate, missing, or
unresolvable checks fail the gate. An unsupported check must fail with its exact
stable planner category, not an unrelated execution or linkage failure. Existing
`link-only` faulting rows remain link-only: this slice does not add panic recovery
or continue a replay runner after a target panic.

Capture coverage is independent of candidate replay support. A C# component
still runs independent strict native capture when its Rust candidate cannot
replay structured values, setup-backed methods, or async calls. A failed test,
invalid bundle, missing operation, or stale exclusion from a nonselected
producer fails the gate just as it does for the selected producer. The matrix
declares the actual limitation rather than hiding that component's capture.

Registry parity remains a separate exact check. In check mode the selected full
native registry must byte-match the checked-in canonical registry. Every other
independent producer is compared against that same anchored canonical, not
merely against fresh producer output (which could admit simultaneous drift).
Byte-identical rows require exact bytes. Existing JSON Pointer/value exceptions
must equal the observed difference set with Rust/C# sides preserved regardless
of selected endpoint; new, changed, or disappearing differences fail. The three
exception rows (`comp.app`, `fixture.enum_event`, `fixture.scalar_types`) name
precise known non-equivalences, not blanket equivalence passes. Replay does not
relax registry parity or comparison policy, and unsupported or link-only checks
do not establish behavioral equivalence.

### Remove interim behavioral duplication

Ordinary behavior lives in the paired CTSC fixtures and their native tests.
Delete redundant woven behavioral assertions and their unused fixtures once
generated captures cover them. Keep only distinct weaver mechanics and
session-scoping fixtures separately, with exact matrix source accounting.

Remove manual capture sessions from `CtscFixtures.Tests`. The existing stateful
native tests cover folded setup surfaces. Missing, throwing, and inconsistent
setup cases live in the non-captured weaver test project and call real woven
boundaries. Reuse existing rejection coverage instead of retaining duplicate
manual instrumentation.

### Evidence and boundaries

Byte-check every declared artifact and reject missing, extra, or stale output.
Use the existing native comparator and validators for divergence witnesses over
C# reference recordings and independently replayed Rust candidate traces.
Witnesses cover inputs, results, declared errors, nested calls, and event order.
Test-only fault injection does not modify checked-in goldens or add a behavioral
assertion format. The event-order witness uses Trace Core observations; linked
observation declarations remain unsupported.

C# candidate replay, async or structured candidate invocation, new comparison
policies, and independent-reference scenario matching remain out of scope.

## Consequences

The golden matrix is no longer C# discovery-only. A third or fourth language can
participate through additional implementation endpoints without adding another
language-specific replay field. Implementation support is still explicit; this
decision does not promise a new producer or candidate runner.

This deliberately replaces the issue's literal independent-reference comparison
with replay-based strict behavioral proof. It avoids scenario matching while
retaining independent strict native capture by both producers against one
canonical registry oracle. No per-language registry compatibility reader is
retained. Producer registries, nonselected captures, and candidate outputs are
transient and removed through the normal invocation-scratch lifecycle.
